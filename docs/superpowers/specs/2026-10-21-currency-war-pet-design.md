# 「货币战争桌宠助手」设计文档

日期：2026-10-21 ｜ 状态：已与用户逐节确认通过 ｜ 阶段：阶段 1 实施前

## 1. 背景与目标

《崩坏：星穹铁道》常驻玩法"货币战争"（Currency Wars，自走棋式）官方对战记录只显示最近 10 局、可收藏 20 局，无法查看总时长，无法长期积累复盘数据。调研（2026-10-21，三路并行）确认：

- 该细分方向无成熟开源工具（GitHub 专属仓库约 10 个、最高 145★，复盘统计类空白）；
- 同类信息层工具（抽卡分析、战绩统计、计算器）生态成熟、被官方默许、玩家接受度高；
- 米哈游协议明文禁止第三方软件/内存读取/协议逆向/模拟用户操作（鼠标宏先例），但"纯本地、不碰游戏进程、玩家主动触发"的工具在历年处罚公告中未见被点名。

**产品定位**：一个 Windows 桌面"随宠"式助手——话痨阴阳怪气的小奇美拉桌宠（神似官方随宠"说怪话"，原创素材），负责对局记录与统计呈现，并按事件阴阳怪气地吐槽玩家。

**核心价值**：无限对战记录 + 自动总时长 + 复盘统计，全部对准官方短板。

## 2. 合规边界（硬约束，所有阶段适用）

- ✅ 允许：玩家手动开始/结束记录；点击时截取结算画面做 OCR（只读屏幕）；启动本地游戏进程；本地统计与展示。
- ❌ 禁止：内存读写、DLL 注入、协议抓包、鼠标模拟/自动点击/自动导航、连续监屏状态机（③档，远期也不做）。
- 素材：桌宠形象为原创 SVG 小奇美拉（风格神似、不复刻）；仓库不含官方美术资源；App 内固定显示"© 米哈游版权所有，非官方同人作品"免责声明；不做"防封"宣传；不模仿官方 CV 声线。
- 发布：代码开源（MIT），美术素材可替换目录结构，非商业。

## 3. 阶段划分

| 阶段 | 交付物 | 验收标准 |
|---|---|---|
| 阶段 1 | 桌宠完整交互 + 战绩面板 + 演示数据 | 桌宠会动、点击说话、能拖、右键菜单；点桌宠弹面板，6 模块有假数据；记录开关（道具化）+「货币战争启动!」按钮存在（启动游戏 + 桌宠提醒）；演示数据走真实写入路径 |
| 阶段 2 | 开始/结束记录 + 结算页 OCR | 真实对局：按下记录→打完→结束时自动截结算图→OCR 填胜负/阵容→用户确认入库；识别错可看原图修正 |
| 远期（不承诺） | LLM 台词、素材替换包、数据导出 | 视情况 |

**核心架构原则：UI 只通过 Repository 层读写数据，不关心数据来源。** 阶段 1 的演示数据与阶段 2 的 OCR 数据走同一接口同一张表；阶段 2 是"换写入方"，面板与桌宠零改动。

## 4. 技术选型

- 桌面壳：**Electron**（用户拍板；备选 Tauri 因 Rust 工具链与透明窗坑被否）
- 前端：React + TypeScript + Vite；两个 BrowserWindow 共享渲染代码
- 数据库：SQLite（better-sqlite3，主进程内），Repository 经 IPC 暴露
- 桌宠形象：SVG 原创小奇美拉（黑耳白肚大红眼铃铛），SVG 动画
- 配置：JSON 配置文件（游戏路径、窗口位置、台词开关等），不进数据库

## 5. 进程与模块结构

```
主进程：SQLite + Repository + 台词引擎 +（阶段2）OCR 服务
桌宠窗口：透明无边框置顶 React 窗口（pet-core）
战绩面板窗口：无边框弹出窗口，从桌宠位置旁展开（stats UI）
```

模块边界：
- **record-store**：对局记录唯一读写口（IPC）
- **pet-core**：桌宠形象/动作/气泡（纯表现，不碰数据）
- **dialogue-engine**：事件（win/loss/streak/start/end/idle/launch）→ 台词模板渲染，支持变量 `{streak}` `{winRate}`
- **stats-engine**：SQL 聚合 + 纯函数统计（胜率/时长/羁绊分组/段位）
- **ocr-service**（阶段 2）：结算截图 → 结构化字段，独立可测

## 6. 数据模型

```sql
CREATE TABLE matches (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  started_at      INTEGER NOT NULL,        -- 毫秒时间戳
  ended_at        INTEGER NOT NULL,
  duration_sec    INTEGER NOT NULL,        -- 自动计算总时长（核心痛点字段）
  result          TEXT NOT NULL,           -- 'win'|'loss'|'interrupted'|'suspected'
  lineup_json     TEXT,                    -- 羁绊/阵容数组 JSON
  rank_change     INTEGER,                 -- 段位变化，可 NULL
  season          TEXT,                    -- 赛季标识，段位走势按赛季分段
  source          TEXT NOT NULL,           -- 'demo'|'manual'|'ocr'
  screenshot_path TEXT,                    -- 结算截图留档
  confidence      REAL,                    -- OCR 置信度，低置信度 → suspected
  note            TEXT
);
```

异常语义：中断局 result='interrupted'，识别无把握 result='suspected'，统计分开计算——"只标记不猜测"。原始截图永久留档，识别算法可升级重跑。

## 7. 桌宠交互规格

| 行为 | 规格 |
|---|---|
| 窗口 | ~200×220，透明、无边框、置顶、不抢焦点 |
| 点击 | 随机动作 ×1 + 头顶气泡台词（3~5 秒消散） |
| 待机 | 每 20~60 秒随机播动作（嗷呜叫/蹦蹦跳跳/恭喜发财三件套），偶尔摸鱼吐槽 |
| 拖动 | 按住拖动，位置持久化 |
| 右键 | 菜单：开始/结束记录 · 打开战绩面板 · 货币战争启动! · 设置 · 退出 |
| **记录开关（道具化，用户拍板方案 A）** | 无外挂按钮；桌宠手持小秒表/小本本道具，点道具切换记录状态；记录中道具举高 + 头顶计时气泡 + 台词"老板~我可记着呢~" |
| 货币战争启动! | 设置中配置游戏路径，点击拉起 Star Rail.exe + 桌宠提醒话术；**不做任何自动导航/模拟点击** |

## 8. 台词系统

台词池 JSON 按事件分类：win / loss / streak / start / end / idle / launch。文风统一：以"老板~"开头的反话式夸赞（继承官方"说怪话"神韵），模板支持数据变量（如"28 把上满段位，老板好英明~"）。阶段 1 写 40~60 条基础台词，人工可增补。

## 9. 战绩面板（6 模块，用户全选）

主区：① 总览统计（总局数/胜率/总时长/平均单局时长/最长连胜连败）② 对局列表（时间/胜负/时长/阵容缩略，突破官方 10/20 上限）③ 单局详情（完整阵容/结算截图/段位变化）。分析页签：④ 羁绊胜率排行 ⑤ 段位走势（按赛季分段；对深度玩家附加"本赛季打满段位用时 X 小时/X 把"效率统计）⑥ 时长分析（单局时长分布/活跃时段）。

## 10. 阶段 2：OCR 流程（②档定点识别，非连续监屏）

1. 用户点击"结束记录"→ 主进程对游戏窗口截一张图（desktopCapturer）
2. OCR 定位结算区域 → 识别胜负/阵容/段位变化字段（各字段带置信度）
3. 低置信度字段标 suspected，面板"待确认"队列提示用户核对原图
4. 确认后写入 matches（source='ocr'，screenshot_path 指向原图）

## 11. 错误处理

- 崩溃/断电：记录两段式写入（开始先写 pending，结束才 finalize）；下次启动扫描 pending 补标 interrupted
- 中断局：超时/用户标记 → interrupted，不计入胜负统计
- 识别失败：宁可漏记不产生错记；原图留档可人工补
- 版本改版：连续识别失败 → 降级提示，等待模板更新
